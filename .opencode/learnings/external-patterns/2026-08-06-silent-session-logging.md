Summary
-------
The orchestrator's manual dual-write discipline (hand-editing messages.md + messages.jsonl after every delegation) was replaced by plugin-driven automatic logging. The delegation-observer plugin writes silent JSONL rows (writer:"plugin", row_id, event_uuid) to `.opencode/session/messages.jsonl` + `registry.jsonl`; `messages.md` is now a derived view regenerated by `scripts/session-log render`; a P5 gate tool (`jsonl-cross-check.sh`) verifies registry↔messages completeness (≥99%, ±5s). Verified via P5 smoke 100% (in-universe 8/8) + jsonl-cross-check exit 0.

Findings
--------
- **F1 — `Hooks.tool` registration shape (OpenCode 1.18.x ground truth).** The correct plugin pattern returns `tool:` on the hooks object itself — NOT a separate `{hooks, tool}` shape. (@opencode-ai/plugin npm 1.18.14 current; no breaking changes 1.18.10→1.18.14.)
- **F2 — `appendFileSync` inside a hook handler.** Syntactically valid but undocumented; blocks the event loop (hooks are awaited sequentially). Prefer async writes or fail-soft guards.
- **F3 — No official append-only sidecar pattern.** The official logging channel is `client.app.log()`; a JSONL sidecar is a custom extension.
- **F4 — `tool.execute.after` fires for ALL tools**, including custom plugin tools — gate logic must filter, not assume.

Outcome
-------
- **Status: `worked`.** Adopted silent JSONL sidecar writing via plugin hooks with fail-soft try/catch (console.warn, no rethrow) on both registry and messages writers; `log_decision` tool restricted to orchestrator ("allow" in `.opencode/opencode.jsonc`); verified via P5 smoke 100% (8/8) + jsonl-cross-check gate (`make jsonl-cross-check` exit 0; registry 213 task_success = 205 legacy + 8 in-universe). DIA-051 closed resolved-by-implementation.
