Incident: TUI corruption caused by plugin writing raw stdout (2026-08-09)

- Summary: During a verification run the OpenCode TUI became unusable: the full viewport was overwritten by a flat raw dump of a subagent's chain-of-thought, panels disappeared, and glyphs were garbled. Root cause: a user-level plugin file placed in the runtime plugins directory (`~/.config/opencode/plugins/`) was auto-loaded by the process and emitted full subagent text to process.stdout on `message.part.updated` events.

- Technical cause: OpenCode's TUI in this deployment does not use an alternate screen buffer and `disableStdoutInterception()` is active; plugins that write to stdout therefore paint directly over the terminal render surface. The offending plugin was not part of the repo plugin[] arrays (it was auto-discovered from the user plugins dir) so the behaviour was environment/runtime specific and not recoverable from the repository alone.

- Containment & fix: disable the plugin by renaming it (append `.disabled`) to remove it from auto-discovery; prefer a hard process restart (kill + start) to ensure module cache is cleared. Follow the §10 AI Devtools Modernization Workflow for the permanent fix: ai-specialist gate → owner decision → coder patch → ai-auditor review → follow-ups (F4/F5) and register the conspect and learnings.

- Operational mitigation (for plugin authors & reviewers):
  - Do not write raw stdout or use console.* in plugins that execute inside the OpenCode process.
  - Use the SDK logging API which is TUI-safe: ctx.client.app.log({ body: { service, level: "info", message } }). Verify the SDK version and call shape (v1 vs v2) when authoring plugins.
  - Prefer disabling suspect plugins by renaming them out of the plugins dir during verification runs.

- Recording: a learnings conspect and an openspec-learnings file were created: .opencode/learnings/external-patterns/2026-08-09-tui-plugin-stdout-corruption.md and knowledge/res007-tui-corruption-stdout/. This incident file records the irrecoverable runtime observation and the safe operational mitigations.
