## Description

**Summary:** the orchestrator's system prompt header identifies its model as:

> "You are powered by the model named deepseek-v4-pro. The exact model ID is
> opencode-go/deepseek-v4-pro"

The orchestrator should be running on `deepseek-v4-flash` (the cheaper, faster variant),
not `deepseek-v4-pro` (the more expensive variant). This is a cost-critical issue — every
orchestrator turn, every delegation, every token consumed is being billed at pro rates
instead of flash rates.

The misconfiguration may have been present for multiple sessions, meaning significant
unnecessary cost has been incurred.

**Root cause (to be determined by §10 Phase 1 research):** candidate hypotheses:

1. Model was set to pro in `oh-my-opencode-slim.jsonc` orchestrator preset and never changed
2. A config edit accidentally changed flash→pro
3. A preset selection issue (wrong preset active)
4. Environment variable override

**Desired state:** the orchestrator runs on `deepseek-v4-flash` (model ID:
`opencode-go/deepseek-v4-flash` or equivalent). All orchestrator presets in
`oh-my-opencode-slim.jsonc` that reference the orchestrator's model must use
`deepseek-v4-flash`.

**Why this is a Blocker:** every token processed by the orchestrator — planning, delegation,
tool calls, response synthesis — is billed at pro rates. The cost multiplier (pro vs. flash)
is applied to the largest token consumer in the system. This is an active financial leak
that grows with every session. It must be stopped before any further work.
