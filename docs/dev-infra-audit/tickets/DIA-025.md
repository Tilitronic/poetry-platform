# DIA-025 — lint-staged py glob covers api-server only; analytics escapes ruff

---

- **ID**: DIA-025
- **Title**: lint-staged py glob apps/api-server/\*_/_.py only; analytics .py escaped ruff
- **Area**: python-tooling
- **Severity**: Major
- **Status**: FIXED
- **Discovered**: fix-lane (wave 2) · 2026-08-02

---

## Description

The `lint-staged` config in `package.json` ran `scripts/lint-python-files.sh` only
for `apps/api-server/**/*.py`. Python files under `packages/analytics-pipeline/`
escaped the pre-commit ruff gate entirely — a lint/format defect there would be
committed silently. This contradicted the DIA-013 fix that brought
analytics-pipeline under the Python gates (`make test-python`); the pre-commit path
still missed it. Major because a whole package bypasses the pre-commit lint gate.

## Verification

1. Read the `lint-staged` block in `package.json` → only `apps/api-server/**/*.py`.
2. Stage a deliberately-unformatted `packages/analytics-pipeline/**/*.py` and commit
   → ruff never runs.

## Fix

`e0ac46c` added the `packages/analytics-pipeline/**/*.py` glob to lint-staged and
extended `scripts/lint-python-files.sh` to cover both packages; `feacb1c` synced the
`lint-python-files` bats fixture so the test asserts the two-package scope.

## Re-verify

`lint-staged` in `package.json` now lists both `apps/api-server/**/*.py` and
`packages/analytics-pipeline/**/*.py` → `scripts/lint-python-files.sh`. A staged
analytics `.py` triggers ruff at pre-commit; the corresponding bats fixture
(`T-PY-001`) passes.
