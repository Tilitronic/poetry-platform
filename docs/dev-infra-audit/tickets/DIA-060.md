## Description

**Summary:** the orchestrator's path-scoped read permissions (defined in the system
prompt / permission rules) only allow reads from:
- `.opencode/session/*`
- `docs/dev-infra-audit/NEXT-RUN.md`
- `AGENTS.md`
- `.opencode/practice-protected.md`

The ticket ledger at `docs/dev-infra-audit/tickets/` is NOT in the allowlist. This
means at session boot, the orchestrator cannot directly read open tickets — it MUST
delegate to a subagent (e.g., @code-navigator) to discover them. This is an
unnecessary delegation cost and violates the principle that the orchestrator should
have direct visibility into the project's ticket system.

**Why this is a Blocker:** the orchestrator is the primary session driver. It
decides what to work on from the ticket ledger. Forcing it to delegate ticket
discovery to a subagent at every boot adds latency, burns tokens, and introduces
a brittle dependency — if @code-navigator fails or is unavailable, the orchestrator
has zero visibility into what needs to be done. The orchestrator should own its
primary input channel directly.

**Desired state:** the orchestrator's read permissions should include
`docs/dev-infra-audit/tickets/**/*` so it can read ticket files directly at boot
and during sessions.

**Related:** DIA-059 (the §10 gate plugin, which would enforce the workflow, is
also not yet activated — needs a restart).
