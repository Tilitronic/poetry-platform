# DIA-035 — lint-staged bash -n on .bats files fails pre-commit

---

- **ID**: DIA-035
- **Title**: lint-staged ran bash -n on \*.{sh,bats} → any staged .bats failed pre-commit
- **Area**: js-tooling
- **Severity**: Minor
- **Status**: FIXED
- **Discovered**: fix-lane (wave 2) · 2026-08-02

---

## Description

The `lint-staged` config ran `bash -n` on `*.{sh,bats}`. Bats files use `@test`
blocks and Bats-specific syntax that is **not valid bash**, so staging any `.bats`
file made the pre-commit hook fail (`bash -n` syntax error) — blocking legitimate
test-file commits. Minor because it is a hook misconfiguration, but it broke the
commit flow for test changes.

## Verification

1. Read the `lint-staged` block in `package.json` → `*.{sh,bats}` → `bash -n`.
2. Stage a `.bats` fixture and commit → pre-commit fails on `bash -n`.

## Fix

`b7d4c05` narrowed the glob to `*.sh` only (bash syntax check still applies to shell
scripts; `.bats` is no longer fed to `bash -n`). Self-tested: a staged `.bats` file
now passes the hook.

## Re-verify

`lint-staged` in `package.json` lists `*.sh` → `bash -n` (no `.bats`). Staging a
`.bats` fixture and committing passes the pre-commit hook.
