## Description

Inventory finding: `package.json` declares `prepare: "husky"` and a full
lint-staged config; `scripts/verify-pre-commit.sh` and
`scripts/verify-pre-push.sh` exist and are bats-tested (4 + 4 cases). The hook
scripts **are** git-tracked — `git ls-files .husky/` lists `.husky/pre-commit`
and `.husky/pre-push` (per DIA-008 resolution, commit `6ba7200`); only the husky
v9 scaffolding (`git check-ignore .husky/_`) is gitignored and regenerated by
`pnpm prepare`.

**Corrected premise (2026-08-04):** the original draft premise "no committed
.husky/" was stale — the hooks ARE committed. What remains true, and is the real
gap: the hooks are enforced **only** by git events, developer-local. **No CI
exists** (no `.github/`), and **no Makefile gate runs the hooks**, so a developer
who commits with `--no-verify`, or a fresh clone whose hooks were not regenerated
by `pnpm prepare`, bypasses the entire autofix/verify chain with no gate firing.
Re-scoped 2026-08-04 from "no committed .husky/" to "not CI-enforced (no CI
exists)" and downgraded Medium → Minor (hygiene/enforcement gap — no gate
impact). The commands in Verification settle the committed-state question; the
enforceable-gap part stands regardless.

## Verification

1. `git ls-files .husky/` → record which hook files are tracked (2026-08-04: `pre-commit`, `pre-push`).
2. `git check-ignore .husky/_` → husky v9 scaffolding is gitignored/regenerated by `pnpm prepare`; confirm `core.hooksPath` wiring (`git config core.hooksPath`).
3. `grep -rn "verify-pre-commit\|verify-pre-push\|lint-staged" Makefile .github/ 2>/dev/null` → confirm no gate or CI enforces the hooks.
4. Confirm `pnpm prepare` regenerates hooks from the tracked files on a fresh clone (`pnpm install` in a clean checkout).
5. Record results in Re-verify.
