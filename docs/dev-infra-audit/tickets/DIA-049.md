## Description

`apps/publishing-platform/` contains only a `package.json` — **no `dev`/`build`
scripts** (`"scripts": {}`), no `src/`, no `dist/`. Nothing binds host port 3000
(compose maps `${PUBLISHING_PORT:-3000}:3000`), so the browser E2E (DIA-042)
got `ERR_CONNECTION_REFUSED` at `http://localhost:3000/`. `api-server` (:8000)
is Python/FastAPI with no dev server running either.

The Docker smoke test only probes author-studio `:9000`, so this gap was
invisible until the browser E2E actually tried to load the app.

Severity **Medium**: not a gate failure (no gate probes :3000), but a real
functional gap — the publishing-platform app cannot be exercised at all, and
DIA-042 cannot complete while it is a stub.

## Verification

1. `cat apps/publishing-platform/package.json` — confirm `"scripts": {}` (no
   `dev`/`build`) and no `src/`/`dist/` present.
2. `ls apps/publishing-platform/` — confirm only `package.json` (+
   `node_modules` if installed).
3. `pnpm dev` in the app dir → fails with "missing script: dev".
4. `curl -sS -o /dev/null -w '%{http_code}' http://localhost:3000/` (stack up)
   → `000` / connection refused (matches DIA-042 `ERR_CONNECTION_REFUSED`).
5. `docker compose ps` → no container publishes :3000.

## Fix

Proposed (owner disposition pending):

- **Option A — scaffold a runnable dev entry:** give publishing-platform a real
  app (scaffold `src/` + `dev`/`build` scripts per its workspace deps
  `@poetry/visualizer-2d` / `@poetry/visualizer-3d` / `@poetry/data-contracts`)
  so the browser E2E can drive it on :3000.
- **Option B — document as intentionally not-yet-implemented:** record the stub
  status explicitly (README note in the app dir) and mark DIA-042's
  publishing-platform leg as expected-fail / deferred until the app is built.
