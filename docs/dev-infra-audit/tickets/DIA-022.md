# DIA-022 — bootstrap.py ALLOWED_SECRETS 8 vs 5 names

---

- **ID**: DIA-022
- **Title**: tools/opencode-docker/bootstrap.py ALLOWED_SECRETS 8 vs 5
- **Area**: docker
- **Severity**: Minor
- **Status**: FIXED
- **Discovered**: fix-lane (wave 2) · 2026-08-02

---

## Description

`tools/opencode-docker/bootstrap.py` shipped an `ALLOWED_SECRETS` whitelist of 8
names, but the compose stack only mounts 5 (`anthropic_api_key`, `openai_api_key`,
`context7_api_key`, `github_token`, `exa_api_key`). The extra entries
(`google_application_credentials`, `aws_*`) mirror no mounted secret, so the
whitelist did not match reality and gave a false impression of which secrets the
container accepts. The in-code comment requires the whitelist to mirror
`dev-entrypoint.sh` ALLOWED_SECRETS and `scripts/dev-secrets-profile.sh`.

## Verification

1. `grep -n ALLOWED_SECRETS -A 12 tools/opencode-docker/bootstrap.py` → 8 names.
2. Compare against the 5 names `dev-entrypoint.sh`/compose actually mount.

## Fix

`e61c240` aligned `bootstrap.py` `ALLOWED_SECRETS` to the 5-name whitelist: dropped
`google_application_credentials` and `aws_*` (M2 — no service uses them), with the
comment documenting why, so the whitelist mirrors `dev-entrypoint.sh` exactly.

## Re-verify

`ALLOWED_SECRETS` in `tools/opencode-docker/bootstrap.py` is now the 5-name set
`{anthropic_api_key, openai_api_key, context7_api_key, github_token, exa_api_key}` —
identical to `dev-entrypoint.sh` and `scripts/dev-secrets-profile.sh`.
