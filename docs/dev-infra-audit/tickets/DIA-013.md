## Description

`packages/analytics-pipeline/pyproject.toml` declares `asyncio_mode = "auto"` for
pytest but has **no dev dependencies**, **no tests directory**, and **no `[tool.ruff]`
config** — unlike `apps/api-server/pyproject.toml` (pytest>=8, pytest-asyncio, ruff,
line-length 100, E+F+I). `scripts/verify-python.sh` runs `uv venv → ruff check . →
ruff format --check . → pytest` but only against `apps/api-server`; analytics-pipeline
is not covered by any Python gate. Either add real tests + ruff config + dev deps and
cover it in verify-python, or document the intentional gap.

## Verification

1. Read `packages/analytics-pipeline/pyproject.toml` (deps, asyncio_mode, ruff).
2. `ls packages/analytics-pipeline/tests` → confirm absent.
3. Read `scripts/verify-python.sh` → confirm it targets `apps/api-server` only.

## Fix

`48af4fc` closed the gap for `packages/analytics-pipeline`: added dev extras,
`[tool.ruff]` config, a `tests/` dir (`conftest.py` + `test_smoke.py`, 4 tests),
extended `scripts/verify-python.sh` and `make test-python` to cover **both**
packages.

## Re-verify

`make test-python` runs `apps/api-server` **and** `packages/analytics-pipeline`;
analytics tests (4) pass; `[tool.ruff]` present in analytics `pyproject.toml`;
`verify-python.sh` covers both packages.
