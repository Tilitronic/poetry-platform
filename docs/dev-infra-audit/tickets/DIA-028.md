# DIA-028 — no pip-audit capability

---

- **ID**: DIA-028
- **Title**: no pip-audit capability
- **Area**: deps
- **Severity**: Medium
- **Status**: FIXED
- **Discovered**: fix-lane (wave 2) · 2026-08-02

---

## Description

The repository had **no Python dependency vulnerability audit capability**: nothing
scanned `apps/api-server` or `packages/analytics-pipeline` dependencies for known
advisories, so the Python side of the dependency story (unlike the JS side) had zero
supply-chain visibility. Medium because the gap is a missing capability rather than
an active defect — but it leaves Python advisories undetected.

## Verification

1. `make help` / Makefile targets → no `audit-python` or pip-audit target exists.
2. `command -v pip-audit` → not installed / not wired into any gate.

## Fix

`a205849` added `make audit-python`: it exports each package's locked dependency set
(`uv export --no-dev`) and audits it with a pinned `uvx pip-audit@2.10.1
--disable-pip -r`. `5b24c87` made the target audit **both** packages and aggregate
the exit code so a finding in one package still fails the target.

## Re-verify

`make audit-python` runs against both packages (`apps/api-server`,
`packages/analytics-pipeline`), returns an aggregate exit code, and the gate is
registered in the Makefile `.PHONY` list and help text.
