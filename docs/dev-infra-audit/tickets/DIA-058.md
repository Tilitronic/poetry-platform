## Description

**Summary:** the `@researcher` subagent returns a structured findings header that includes
`PERSISTENCE_RECOMMENDED: true` when the research warrants persistent knowledge artifacts
(conspect + shelf entry). However, the orchestrator (and the system as a whole) does NOT
automatically trigger the `research-pipeline` skill (researcher → conspecter → memory shelf)
when this flag is returned. Research findings with persistence recommendations are lost —
they exist only in the conversation transcript — unless the developer manually intervenes
and explicitly dispatches the pipeline.

**Evidence (this session):** researcher task `res-1` (session
`ses_024f0b48effeHUn16O36WcOR6l`) researched "OpenCode path-triggered hooks" with 22
external sources across 6 domains, returned `PERSISTENCE_RECOMMENDED: true` in its
findings header, but no conspect or knowledge artifact was created. The `knowledge/`
directory received nothing. The findings are conversation-only.

**Root cause hypotheses:**

1. **No mechanical trigger.** The `research-pipeline` skill exists
   (`.opencode/skills/research-pipeline/SKILL.md`) but must be manually invoked by the
   orchestrator. There is no hook, plugin, or orchestrator instruction that mechanically
   reads the researcher's output for `PERSISTENCE_RECOMMENDED: true` and auto-dispatches
   the pipeline.

2. **Advisory-only prompt.** The orchestrator prompt says "When
   PERSISTENCE_RECOMMENDED: true, load the research-pipeline skill for the full pipeline"
   but this is advisory-only — the same enforcement gap as the §10 AI Devtools
   Modernization Workflow (the orchestrator may not read the flag or may skip it under
   time/resource pressure).

3. **No output-parsing layer.** The orchestrator likely lacks the mechanical awareness to
   parse subagent output for structured flags like `PERSISTENCE_RECOMMENDED`. The
   researcher's structured header is designed for machine consumption, but no machine is
   consuming it.

**Impact:** Medium severity. No production risk, but:

- Research investments (token cost, time, source collection) are wasted when findings
  aren't persisted — they evaporate at session end.
- The knowledge base (`knowledge/`) is starved of research artifacts that the researcher
  explicitly flagged as worth persisting.
- This is a recurring, systemic gap — every researcher dispatch with
  `PERSISTENCE_RECOMMENDED: true` will silently fail to persist unless the developer
  notices and manually dispatches the pipeline.

**Relationship to DIA-057:** DIA-057 documents the §11 knowledge-workflow order violation
(research → conspect → analysis). DIA-058 is the mechanical cause: the system has no
trigger for the conspect step. If DIA-058 is fixed (auto-trigger on
PERSISTENCE_RECOMMENDED), DIA-057's order-violation risk is significantly reduced.

## Verification

1. **Reproduce the gap:** dispatch a `@researcher` on a topic that warrants persistence
   (external sources, multi-domain). Confirm the researcher returns
   `PERSISTENCE_RECOMMENDED: true` in its structured header.
2. **Confirm no auto-dispatch:** after the researcher completes, check that no
   `@conspecter` task was spawned, no file written to `knowledge/res*/`, no shelf entry
   created in `.opencode/memory/`. All findings exist only in conversation.
3. **Post-fix acceptance test (when fix is applied):** after researcher completion with
   `PERSISTENCE_RECOMMENDED: true`, verify that within the same session:
   - A `knowledge/res*/sources/` directory is created with downloaded sources
   - A conspect file (`knowledge/res*/<id>-<topic>-conspect.md`) exists
   - The memory shelf entry is updated (`.opencode/memory-shelf.yaml` or equivalent)
   - The orchestrator log shows the auto-trigger event

## Fix

**Applied 2026-08-07 (§10 cycle)** — mechanical trigger implemented:
delegation-observer.ts researcher-lane plugin writes
`persistence-pending.json` on completed results with
`PERSISTENCE_RECOMMENDED: true`; hard-gate fallback in orchestrator_append.md
§Research Persistence Gate; flag contract documented in `agents/researcher.md`.
Fix directions below retained as reference.

**Fix directions (not implemented by this ticket):**

1. **Mechanical trigger (preferred):** add orchestrator instructions (or a plugin/hook)
   that parse subagent output for `PERSISTENCE_RECOMMENDED: true` and auto-dispatch the
   `research-pipeline` skill. The trigger must:
   - Read the researcher's completed output
   - Detect `PERSISTENCE_RECOMMENDED: true`
   - Auto-load the `research-pipeline` skill (which chains researcher → conspecter →
     memory shelf)
   - Verify artifact creation before marking the pipeline complete

2. **Fallback: hard gate.** If mechanical auto-trigger is infeasible, make the
   orchestrator refuse to close a researcher lane with `PERSISTENCE_RECOMMENDED: true`
   until the pipeline artifacts (sources/ + conspect + shelf entry) are confirmed to
   exist. This is a hard-block approach — same enforcement pattern as the DIA-057 fix
   recommendations.

3. **Document the flag contract.** The `PERSISTENCE_RECOMMENDED` flag in the researcher's
   output header should be documented as a machine-readable contract, not just advisory
   text. The researcher's agent definition and the orchestrator's prompt should both
   reference this contract.

**§10 routing note:** if the fix touches `.opencode/` agent definitions, orchestrator
prompts, or plugin config, route through §10 (AI Devtools Modernization Workflow) when
implemented.
