# DIA-012 — .env missing CONTEXT7_API_KEY

---

- **ID**: DIA-012
- **Title**: .env missing CONTEXT7_API_KEY vs .env.example
- **Area**: env
- **Severity**: Minor
- **Status**: FIXED
- **Discovered**: inventory N5 (baseline env diff) · 2026-08-02

---

## Description

The gitignored `.env` has 6 keys (`POSTGRES_*`, ports) but is **missing**
`CONTEXT7_API_KEY` which `.env.example` declares. The compose `:-` default makes this
non-fatal (context7 falls back to dry-run), but any live context7 MCP/doc fetch
requires the key. Tracked as a pending user step — document the required action in
the ticket when resolved.

## Verification

1. Diff key sets: `envsitter`/manual compare `.env` vs `.env.example` keys.
2. Confirm `CONTEXT7_API_KEY` absent from `.env` and present in `.env.example`.

## Fix

**Local-only fix**: `CONTEXT7_API_KEY` appended to the gitignored `.env` from
`secrets/context7_api_key`. Because `.env` is gitignored, nothing is committed —
fresh clones still need the manual key step (documented in CHANGELOG P9).

## Re-verify

`.env` now contains `CONTEXT7_API_KEY` (local machine only); `git status` shows no
`.env` change (gitignored). Fresh clones require the manual key per CHANGELOG P9.
