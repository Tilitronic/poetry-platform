# DIA-031 — API keys passed as container env (docker inspect leak)

---

- **ID**: DIA-031
- **Title**: 5 API keys passed as container env (docker inspect leak)
- **Area**: docker
- **Severity**: Low
- **Status**: FIXED
- **Discovered**: fix-lane (wave 2) · 2026-08-02

---

## Description

The compose stack passed 5 API keys to containers as plain environment variables.
`docker inspect` exposes container env, so anyone with host access could read the
secret values in clear text — a secret-leak vector that the secrets/ design
(`/run/secrets` mounts) was meant to avoid. Low because it required host-level
access, but it undermined the whole secrets story.

## Verification

1. `docker compose config` → 5 API-key environment entries visible in plaintext.
2. `docker inspect <container>` → same keys readable.

## Fix

`fa272f3` removed the env passthrough entirely: `docker compose config` is now clean
of API-key variables, and `dev-entrypoint.sh` loads secrets from `/run/secrets`
only.

## Re-verify

`docker compose config` shows **no** API-key environment entries; secrets are
sourced exclusively from the `/run/secrets` mount in the entrypoint.
