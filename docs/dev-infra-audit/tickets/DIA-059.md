## Description

**Summary:** the §10 gate plugin (implemented in cycle `c-20260807-gate-plugin` as ~130 new
lines in `.opencode/plugins/delegation-observer.ts`) was never activated because OpenCode
was **not restarted** after the plugin change. The gate code exists on disk and passes
`tsc` + `test-config`, but the old plugin binary (without the gate) is still loaded in the
runtime. As a result, `.opencode/` file edits in the current session bypassed the §10
workflow entirely — the orchestrator dispatched `@coder` to edit `.opencode/` files without
a gate-token, and the gate did not fire.

**Why this is a Blocker:** the §10 gate is the **sole mechanical enforcement** of the AI
Devtools Modernization Workflow (AGENTS.md §10, AGENTS.md §2.5). Without it, `.opencode/`
edits are gated only by advisory text in the orchestrator's system prompt — which can be
(and was) skipped. The gate is the only thing that prevents this class of process violation.

**Root cause:** OpenCode was never restarted after the plugin was modified in cycle
`c-20260807-gate-plugin`. The HANDOFF.md exit_state is `manual-halt` with the explicit
note: "plugin needs OpenCode restart; post-restart gate test pending." This restart step
was not performed before the next session began.

**Evidence:**

1. **HANDOFF.md exit_state = manual-halt** — the previous session explicitly documented
   that a restart was needed: "plugin needs OpenCode restart; post-restart gate test
   pending" (HANDOFF.md L4, L45 — "OWNER RESTART OpenCode — plugin changes go live on next
   run").

2. **Gate code exists on disk and compiles.** `delegation-observer.ts` L499-555 contains the
   `tool.execute.before` gate: intercepts `edit`/`write`/`apply_patch` on `.opencode/**` and
   `AGENTS.md`, checks `gateTokenValid()`, throws `§10 GATE:` error if no token exists.
   `tsc --noEmit` passes, `test-config` passes.

3. **In current session (ses_024ddc0b6ffenyneU5XpCYQ4qN), @coder successfully edited
   `.opencode/` files** — `.opencode/plugins/delegation-observer.ts`, `NEXT-RUN.md`, and
   5+ other `.opencode/` files — no gate blocked any of them.

4. **No gate-token was logged** by the orchestrator before dispatching these edits. This
   is a §10 workflow violation — the gate should have blocked it.

5. **Process violation amplification:** beyond the silent gate failure, the orchestrator
   in this session bypassed the §10 workflow (no `@ai-specialist` gate research before
   `.opencode/` edits). This is the exact class of violation the gate is supposed to
   prevent. Once the gate is active, this cannot happen.

## Fix

**Applied 2026-08-07** — root cause: `tool.execute.before` hook args contract. The before-hook
receives `(input, output)` where tool arguments live in **`output.args`**, NOT `input.args`
(`input` is read-only `{ tool, sessionID?, callID?, directory? }`). Reading args from
`input.args` yields `undefined` at runtime, so `filePath` guards silently never fired → the
gate was fail-open despite the plugin being live post-restart.

2-line change in `.opencode/plugins/delegation-observer.ts`:

1. **L482:** `async (input, _output)` → `async (input, output)` — the before-hook now names the
   `output` parameter and reads args from it.
2. **L514:** `(input as unknown as { args?: unknown }).args` → `(output as unknown as { args?: unknown }).args` — tool arguments read from `output.args` (the mutable args carrier), not `input.args`.

Note: after-hooks (`tool.execute.after`) DO read `input.args` — that is the correct contract
for after-hooks; they were intentionally left unchanged.

**Verification evidence:**

- `npx tsc --noEmit --strict --skipLibCheck --target ESNext --module preserve --moduleResolution bundler .opencode/plugins/delegation-observer.ts` → exit 0
- `make test-config` → exit 0
- Phase 6 independent audit: **APPROVE-WITH-NOTES** (ai-auditor ses_0247422b5ffe7hA6yrWqmJXUk5) — advisory notes: verify apply_patch edge case (non-`Index:` first line) post-restart; add CI regression grep for `tool.execute.before` + `input.args` misuse.

**Remaining (runtime-dependent):** the gate goes live only after an OpenCode restart. Gate
smoke verification (blocked → gate-token → allowed → cleared → blocked) is pending restart —
see Re-verify below. Status is IMPLEMENTED (fix applied + verified statically), not VERIFIED
(gate smoke requires the restarted runtime).
