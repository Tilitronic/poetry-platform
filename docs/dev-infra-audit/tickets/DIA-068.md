## Description

The research-persistence mechanical trigger (DIA-057/058) is broken.
delegation-observer.ts (`.opencode/plugins/delegation-observer.ts`,
tool.execute.after hook L709-762) writes
`.opencode/session/persistence-pending.json` when
AND(isResearcherLane, `/state:\s*completed/i`, `/PERSISTENCE_RECOMMENDED:\s*true/i`)
— but the actual OpenCode task() tool output uses XML-attribute form
`<task id="..." state="completed">`, NOT the colon/header form `state: completed`
the regex demands.

**Verified programmatically:** on real runtime output,
`/state:\s*completed/i` → false, flag regex → true, AND → false → file NEVER
written.

**Evidence:** res-1 and res-2 smokes both returned `PERSISTENCE_RECOMMENDED:
true`, no `persistence-pending.json` ever appeared; plugin loaded (registry.jsonl
rows being written live); trigger never fired (no 'persistence flag:' log, no
write-failure warning). Root-cause session: cod-4 (ses_0211b6e98ffelpQq6owaaKkMmy).

**Impact:** Major — silent failure of a documented mechanical gate;
DIA-057/058 NOT VERIFIED; research findings with `PERSISTENCE_RECOMMENDED`
keep being lost (conversation-only) unless the developer intervenes manually.

## Verification

1. Inspect `.opencode/plugins/delegation-observer.ts` L736 (state-check regex
   `/state:\s*completed/i`).
2. Reproduce with a real task() output sample in XML-attribute form —
   confirm `/state:\s*completed/i` does NOT match.
3. Post-fix: dispatch researcher returning `PERSISTENCE_RECOMMENDED: true`;
   assert `.opencode/session/persistence-pending.json` IS written.

## Fix

**Fix direction:** L736 → form-tolerant regex e.g.
`/state\s*[:=]\s*["']?completed/i` (matches both colon and XML-attribute
forms), or drop the redundant state check (a returned task output with
`<task_result>` + flag already implies completion).

**Routing note:** plugin code fix — per global AGENTS.md §10 workflow, route
through @coder implement → @reviewer or @ai-specialist review per change type
(the ai-specialist gate is for config changes; this is a plugin code fix).

**Applied 2026-08-08 (implementation lane ses_01ffd9279ffetxzRDk7N7YF3dH):**

- `.opencode/plugins/delegation-observer.ts` L736 (committed baseline; L739 in
  working tree after comment rewrite):
  `/state:\s*completed/i` → `/state\b\s*[:=]\s*["']?completed["']?/i` —
  form-tolerant: XML attribute form primary (`state="completed"`), colon form
  fallback (`state: completed`), optional quotes.

  `parseTaskStateFromOutput`, XML attribute form is primary, `state: completed`
