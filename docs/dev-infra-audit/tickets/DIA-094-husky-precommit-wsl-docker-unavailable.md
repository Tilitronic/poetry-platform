## Description

**Summary:** the husky pre-commit hook cannot run in this WSL distro because it
requires the dev container (docker), and docker is unavailable here: Docker
Desktop's WSL integration is inactive (the `docker-desktop` WSL distro is
Stopped and Docker Desktop is not running), no Linux docker-engine is
installed in the distro, and there is no `/var/run/docker.sock`. Session-6
commit `9662f28` was therefore committed with `git commit --no-verify`,
skipping the container-based lint-staged autofix gate. Host-runnable checks
(the `/home/qualt` guard + `npx lint-staged` with a fake/no container path)
were run manually and passed (exit 0), but the container-based checks were
skipped, weakening the commit quality gate.

### Hook design (what the hook does, and where it decides container vs host)

Wiring (husky v9, `core.hooksPath = .husky/_`, regenerated by `pnpm prepare`):

- `.husky/pre-commit` (6 lines) delegates to the gate script and documents the
  bypass:

  ```
  1: #!/usr/bin/env bash
  2: # Run lint-staged (auto-fix staged files) before every commit. The gate lives
  3: # in scripts/verify-pre-commit.sh, which handles host vs dev-container
  4: # execution and fails when the dev container is down (start with `make up`,
  5: # or bypass explicitly with `git commit --no-verify`).
  6: bash scripts/verify-pre-commit.sh
  ```

- `scripts/verify-pre-commit.sh` (81 lines) is the gate:
  - **Execution contexts (lines 5-12):** inside the dev container -> run
    `npx lint-staged` directly in `/workspace`; on the host -> delegate via
    `docker compose exec dev`. Unlike pre-push (which warns and passes when the
    container is down), this hook FAILS by default (D1) so a commit-time
    autofix gate can never silently skip. Documented escape hatches:
    `make up` to start the stack, or `git commit --no-verify` to bypass
    explicitly (line 12).
  - **Container-path decision:** `is_in_dev_container()` (lines 24-26) checks
    `[ "$(hostname)" = "poetry-dev" ]`; `container_running()` (lines 28-30)
    checks `docker compose -f "$ROOT/docker-compose.yml" ps --services --status running | grep -qx "dev"`.
    `run_workspace()` (lines 34-42) runs `npx lint-staged --allow-empty`
    directly inside the container, or on the host via
    `docker compose -f ... exec -T dev bash -lc "cd /workspace && npx lint-staged --allow-empty"`.
  - **Guard logic:** `guard_no_home_qualt()` (lines 44-62) greps
    `$COMMANDS_DIR/*.md` (default `$ROOT/.opencode/commands`) for the literal
    `/home/qualt` and exits 1 on any hit; it is fired at line 66, BEFORE any
    container detection/delegation, so it runs on the host even when the dev
    container is down.
  - **Container-down path (lines 68-76):** if not inside the container and
    `container_running` fails -> prints
    `!! dev container not running - start with 'make up', then commit again.`
    and `exit 1`.

**Conclusion (precise reason):** docker is not installed as a Linux engine in
this distro, and Docker Desktop's WSL integration is NOT active for it. The
`docker` command on PATH is Docker Desktop's Windows-side launcher shim; when
WSL integration is not enabled / Docker Desktop is not running (the
`docker-desktop` WSL distro is Stopped), the shim refuses to work with
"The command 'docker' could not be found in this WSL 2 distro" (exit 1). There
is no `/var/run/docker.sock`, no `docker.service`, and no `/mnt/wsl/docker-desktop`
mount. Hence every docker-dependent branch of the hook fails, and the hook
hard-fails (D1 design), forcing `--no-verify`.

## Fix

> To be filled at fix time. Proposed options (from the coder lane, 2026-08-11):

### Option A - Install/configure Docker so the container path works as designed

Enable Docker Desktop WSL integration for this Ubuntu distro (Settings > Resources

> WSL integration, then start Docker Desktop) and/or install docker-engine
> inside WSL (apt install docker.io + daemon) so `docker compose` works natively.

- Pros: the hook keeps its designed behavior (containerized lint-staged, same
  toolchain as the dev container); no hook logic changes; strongest guarantee
  that host and container checks agree.
- Cons: requires Docker Desktop running on Windows (or a Linux docker daemon)
  as a permanent host dependency; heavier operational burden; does not fix the
  "container down" case for developers who do not run docker at all; still
  fails on machines without docker.

### Option B - Graceful degradation in the hook (REJECTED per developer directive 2026-08-11)

When docker is unavailable (`container_running` fails), automatically run the
equivalent host-side checks (guard_no_home_qualt + `npx lint-staged
--allow-empty` on the host, plus `make test-config` if cheap) and only then
allow the commit - no manual `--no-verify` bypass needed. The container path
remains the primary path when docker IS available.

- Pros: removes the forced `--no-verify` bypass entirely (the developer's core
  objection); keeps the quality gate effective in WSL without docker; uses
  existing host tooling (eslint/prettier/ruff/bash-n via lint-staged are
  installed in the repo); smallest behavioral surprise - commit just works;
  matches pre-push's existing warn-and-degrade philosophy but keeps the gate
  (fail on lint errors instead of failing on docker).
- Cons: host lint-staged uses host node_modules versions instead of the
  container's pinned toolchain (minor skew risk); needs a clear "degraded
  mode" log line so the developer knows the container path was skipped;
  requires updating `verify-pre-commit.sh` + its 4 bats tests (D1 semantics
  change from "fail when container down" to "fall back to host checks").
- **Status: REJECTED (2026-08-11).** The follow-up developer directive makes a
  running docker dev container a hard prerequisite for implementation work AND
  commits; degrading to host checks would still let commits land without the
  container, which is exactly what the directive forbids.

### Option C - Split the hook: host checks always on, container checks optional

Make the pre-commit hook run only fast host checks (guard + lint-staged on
host) unconditionally, and move the container-based verification into an
optional staged gate (e.g. a pre-push step or a `make verify` companion) that
runs only when the container is up.

- Pros: commits are never blocked by docker; fast local autofix on every
  commit; clean separation of "cheap local hygiene" from "full container
  verification".
- Cons: weaker gate - container-based checks move later in the workflow (push
  time or manual), so a commit can still carry issues that only the container
  toolchain would catch; pre-push already warns-and-passes when the container
  is down, so the container checks can be silently skipped entirely; more
  design surface (new gate wiring + docs).

### Recommendation

**Option A.** The follow-up developer directive (2026-08-11) makes docker a
hard prerequisite: implementation work AND commits MUST NOT proceed without a
running docker dev container, and working around the gate (--no-verify, manual
host checks) is categorically unacceptable. Therefore the fix is to make docker
AVAILABLE (enable Docker Desktop WSL integration for this Ubuntu distro and/or
install docker-engine in the distro) and to remove/disable the `--no-verify`
bypass so the hook HARD-FAILS (blocks the commit) whenever the container is
down. Option B (graceful degradation to host checks) is REJECTED per the
developer directive - it would still allow commits without the container.
Option C weakens the gate and is the least aligned with the directive.
