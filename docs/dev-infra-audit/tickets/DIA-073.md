## Description

**Summary:** `.opencode/session/current-handoff.json` is a SINGLE shared file per
working directory (gitignored via `.gitignore:79`, the `.opencode/session/` directory
rule). Two parallel OpenCode sessions working in the same directory that each write a
handoff CONFLICT: **last-writer-wins** — the second write clobbers the first's
prognosis. DIA-061's checksum gate fails-closed on SHA256 mismatch (catches silent
clobbering at boot), but the lost prognosis still needs recovery.

**Facts from developer discussion (2026-08-09, plugin-removal campaign session):**

1. **Single shared file per working dir.** NEXT-RUN.md §1 (boot sequence item 1) and
   §7.3 (incoming boot, steps 0–1) both assume a deterministic single path
   `.opencode/session/current-handoff.json` via direct `read()` (no glob). The whole
   `.opencode/session/` directory is gitignored (`.gitignore:79`) — transient,
   regenerated per session.
2. **Last-writer-wins conflict.** Two parallel sessions in the same directory each
   write that one path. Per HANDOFF-REFRESH (G2) the handoff file is REWRITTEN (whole
   file, not appended) at each campaign milestone — so the second writer's file fully
   replaces the first's, including the first's "Prognosis for next cycle".
3. **DIA-061 detects, does not recover.** The checksum gate (SHA256 over the prognosis
   section vs `checksum` field) fails-closed at boot on mismatch — it flags
   tampering/corruption and escalates to the developer, but the clobbered prognosis
   content itself is gone and must be manually reconstructed.
4. **Sessions are uniquely identifiable.** Sessions have their own IDs, persistent
   across sessions in the OpenCode DB at `~/.local/share/opencode`;
   `registry.jsonl` cross-references ticket↔lane↔session_id (A2); native recall via
   `session.prompt({path:{id}})`.
5. **Developer hypothesis.** Since sessions have unique identifiers, handoff
   coordination could leverage them — e.g. per-session handoff files, an
   owner-session field + merge/lock protocol, or a registry-based pointer resolving
   which session owns the active handoff.

**What ALREADY protects against loss:** per-session `messages.jsonl` logs
(plugin-managed), `registry.jsonl` cross-refs (A2), and native session recall — the
**actual gap** is only the boot-gate convenience file being single/shared.

**Root cause:** handoff state is modeled as a single per-directory file even though
the actors (sessions) are many and uniquely identified. The single-writer assumption
breaks under parallelism.

**Impact:** Medium. Parallel sessions in the same directory (or a stale/foreign
handoff left by a previous session) can silently lose a predecessor's prognosis;
DIA-061 detects the corruption but cannot recover it; recovery requires manual
reconciliation from messages.jsonl / registry.jsonl.

## Verification

1. Reproduce: start two parallel OpenCode sessions in the same working directory;
   have each write `.opencode/session/current-handoff.json` — observe last-writer-wins
   (the second write's prognosis fully replaces the first's).
2. Confirm the shared-file design: `.gitignore:79` ignores the whole
   `.opencode/session/` dir; NEXT-RUN.md §1 (item 1) and §7.3 (steps 0–1) read the

3. Confirm DIA-061 checksum-gate behavior: boot-time SHA256 mismatch → fails-closed
   escalation to developer (detects clobbering, does not recover content).
4. Confirm the session-identity substrate: `~/.local/share/opencode` DB keeps session
   IDs across sessions; `registry.jsonl` rows map ticket↔lane↔session_id (A2).
5. Post-investigation (acceptance): see Re-verify.

## Fix

**Fix direction (investigation scope — research ticket, no implementation):**

- **(a) Per-session handoff files.** `current-handoff-<session_id>.json` naming — how
  the boot gate resolves which to load (most recent? explicit `--resume <session_id>`?);
  checksum per file.
- **(b) Owner-field + conflict protocol.** Handoff carries `owner_session_id`; a
  concurrent writer detecting a foreign owner either queues (append to registry, not
  clobber) or merges; DIA-061 checksum extended to cover the owner field.
- **(c) Registry-based pointer.** `registry.jsonl` (A2) already maps session_id; a
  pointer file (e.g. `current-handoff-pointer.json`) references the owning session's
  handoff — atomic swap via rename.
- **(d) Compare with the `worktrees` skill (already installed).** Separate checkouts
  give separate `.opencode/session/` dirs — is that the sanctioned answer for true
  parallelism, with in-directory parallel sessions limited to ONE handoff owner and
  others relying on their own messages.jsonl + session recall?
- **Document the baseline:** what ALREADY protects against loss (per-session
  messages.jsonl logs, registry.jsonl cross-refs, session recall via native API) and
  what the ACTUAL gap is (only the boot-gate convenience file is single/shared).

**Routing note:** the handoff protocol is process/design-governed (NEXT-RUN.md §7,
`openspec/changes/dia-redispatch-cycle/`); any change to agent/config/skill surface is
§10-routed (global AGENTS.md §10). This ticket records the gap and the investigation;
the adopted fix is a separate work item.
