## Description

The postgres service used the well-known default credential `poetry` (user/password
and database name all defaulting to the project name). A predictable default
credential is a weak spot for any container reachable beyond localhost; at minimum
it must be explicitly documented as dev-only. Low because the compose port mapping
is local dev, but the default is guessable.

## Verification

1. `grep -n "poetry" docker-compose.yml .env.example` → default credential present
   with no dev-only guard.

## Fix

`868e226` added dev-only guard comments documenting the credential as a local-dev
default (deliberately **no** variable validation, to keep `make up` working without
requiring env setup).

## Re-verify

`docker-compose.yml` / `.env.example` document the `poetry` credential as
dev-only; `make up` still works unchanged.
