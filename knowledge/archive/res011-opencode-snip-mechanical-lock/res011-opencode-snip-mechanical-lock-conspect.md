Res011 — OpenCode Snip: mechanical lock & removal assessment

Created: 2026-08-11

Summary
This conspect synthesizes archived sources relating to the opencode-snip plugin (opencode-snip@1.6.1) and the separate snip binary (edouard-claude/snip). It documents: the plugin's identity and mechanism; concrete breakage classes reported by users and upstream issues; snip binary capabilities and config surface; native OpenCode alternatives; community command-rewriter plugin patterns; and a removal-risk assessment with recommended remediation. All claims cite locally archived source files (MLA-style entries follow each claim).

1. opencode-snip@1.6.1 — identity & mechanism
- Identity: opencode-snip is an OpenCode plugin that registers a tool.execute.before hook which rewrites (prefixes) every shell command the agent issues so the runtime sees "snip <original-command>" instead of the original invocation. (See archived package page and GitHub repository.) [VincentHardouin opencode-snip; npm package] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-VincentHardouin-opencode-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/www-npmjs-com-package-opencode-snip.md)
- Mechanism: the plugin's use of tool.execute.before performs a command rewrite at the OpenCode hook layer (no filter transform inside OpenCode itself). The practical result is that the original verbatim command string used for permission matching is mutated (prefixed) before OpenCode's permission rules evaluate it. [opencode-snip docs] (knowledge/res011-opencode-snip-mechanical-lock/sources/www-npmjs-com-package-opencode-snip.md)
- Config surface: repository and package docs show the plugin requires no additional OpenCode configuration beyond installing the plugin entry (zero config surface). [npm package metadata] (knowledge/res011-opencode-snip-mechanical-lock/sources/www-npmjs-com-package-opencode-snip.md)
- Dependents: npm page and repo show no downstream dependents recorded (registry metadata indicates no dependents). This supports low coupling for removal. [npm package metadata] (knowledge/res011-opencode-snip-mechanical-lock/sources/www-npmjs-com-package-opencode-snip.md)

2. Permission-matching breakage (issue #7)
- Concrete report: issue #7 (opencode-snip GitHub) documents that because the plugin prepends "snip" to every command, fine-grained bash permission rules that match exact command patterns (e.g., "git log *") are no longer effective — the effective command becomes "snip git log ..." and thus fails to match existing allow/deny rules. The issue contains user-provided permission JSON demonstrating the failure. [Issue #7] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-VincentHardouin-opencode-snip-issues-7.md)

3. Other breakage classes observed across sources
- SSH and remote invocation interference (#23 class noted in community reporting): filters and path-compacting actions can alter or drop SSH output or prompts when pipeline actions make path substitutions. Evidence: snip filter docs and community issue threads describing SSH-output-sensitive filters. [snip repo & filters] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip-wiki-Integration.md)
- Environment-variable leakage / token-claim patterns (#22): community posts and analysis (developer blog) discuss token-optimization trade-offs and cases where a tool that rewrites commands can alter env var visibility to permission or auditing layers. [developer upsun post; snip docs] (knowledge/res011-opencode-snip-mechanical-lock/sources/developer-upsun-com-posts-ai-opencode-token-optimization.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md)
- Windows & platform differences (#20): snip's install and hook mechanisms describe platform-specific installers and integration steps (Homebrew / Go / Windows builds noted), and community pull requests raise Windows-specific concerns. [snip repo; PRs] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip-pull-70.md)
- Semicolon / compound-command edge-cases (#27): command-rewriting that naively prefixes commands can change shell parsing for multi-command lines ("cmd1; cmd2") or pipelines; community discussions and the snip documentation call out runner/wrapper detection and transparent_prefixes, but mismatches remain a reported class of failure. [snip docs + opencode tool handler code] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-sst-opencode-blob-dev-packages-opencode-src-tool-truncate-ts.md)
- Stacking / recursive rewriting (#15 snip-on-snip): reported pull requests and issues document cases where multiple wrappers or repeated prefixing (snip + another prefix) can stack, producing incorrect commands or confirmations. [opencode-snip PRs / issue threads] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-VincentHardouin-opencode-snip-pull-14.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-VincentHardouin-opencode-snip-pull-13.md)
- Unconfigured noise / fail-open behavior (#16): configuration defaults such as "on_error: passthrough" and tee modes create cases where noise or unexpected fallback output may reach the LLM; unconfigured environments can therefore manifest unexpected behavior. [snip config docs] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md)

4. The snip binary (edouard-claude/snip) — capabilities & config surface
- snip binary is an external CLI token-optimizer separate from opencode-snip; it implements a "proxy" mode (snip proxy) for passthrough, a tee directory for capturing filtered output, and a TOML config that exposes SNIP_DB_PATH, SNIP_TEE_DIR, SNIP_TEE, SNIP_CONFIG (environment and config knobs). There is no documented SKIP_SNIP env var; control is via explicit proxy or config. [snip repo + wiki] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip-wiki-Configuration.md)
- Bypass mechanisms: snip exposes "snip proxy -- <command>" and runner-transparent_prefix options and a tee fail-open mode; community docs show no plugin-level global "bypass" flag — bypass is explicit via proxy or configuration. [snip docs] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md)

5. Native OpenCode alternatives / mitigation knobs
- OpenCode native configuration provides tool_output.max_lines (2000) and max_bytes (~50KB) caps, compaction features (auto/prune/reserved), and environment-control flags (OPENCODE_DISABLE_AUTOCOMPACT, OPENCODE_DISABLE_PRUNE, OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX). The OpenCode docs and code (config.ts, truncate.ts) describe truncation and compaction semantics as an alternative to an external command-rewriter plugin. [OpenCode docs & source] (knowledge/res011-opencode-snip-mechanical-lock/sources/opencode-ai-docs-config.md; knowledge/res011-opencode-snip-mechanical-lock/sources/opencode-ai-v2-docs-compaction.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-sst-opencode-blob-dev-packages-opencode-src-config-config-ts.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-sst-opencode-blob-dev-packages-opencode-src-tool-truncate-ts.md)

6. Upstream opencode issues of interest
- Issue #18108 — doom_loop / truncation failure class: archived issue shows a truncation/doom_loop failure class in the OpenCode codebase that can interoperate badly with command rewriters that change output lengths or add markers. [anomalyco issue 18108] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-anomalyco-opencode-issues-18108.md)
- Issue #31680 — tool.execute.before arg-mutation bug: describes a bug class where tool.execute.before hook mutates arguments unexpectedly (arg mutation leading to runtime mismatch). This directly intersects with opencode-snip's approach. [anomalyco issue 31680] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-anomalyco-opencode-issues-31680.md)
- Issue #5894 — subagent hook bypass: discusses subagent hook bypasses that allow execution outside the primary permission flow (relevant for attack surface analysis). [anomalyco issue 5894] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-anomalyco-opencode-issues-5894.md)

7. Community command-rewriter plugins — pattern and bypasses
- Surveyed projects (agentguards-plugins, opencode-bash-guard-plugin, opencode-fence) show a common design pattern: the plugin implements explicit bypass/escalation controls (e.g., env flags like FENCE_SANDBOX=1, agent-specific deny-bridges, or project-local allowlists) and surface similar edgecases (permission matching, semicolon parsing, platform-specific behavior). [agentguards, bash-guard, fence] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-alelaguard-agentguards-plugins.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-heimoshuiyu-opencode-bash-guard-plugin.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-fencesandbox-opencode-fence.md)

8. Removal-risk assessment
- Coupling: archived npm/registry and repo pages show no recorded downstream dependents; the plugin is primarily a local-install opt-in plugin. This yields low coupling and low removal blast radius. [npm registry / repo] (knowledge/res011-opencode-snip-mechanical-lock/sources/www-npmjs-com-package-opencode-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-VincentHardouin-opencode-snip.md)
- Token-claim conditional: snip introduces token-savings claims (measured percentages) and tracking telemetry via a local SQLite DB / tee; removal will impact token accounting but not core OpenCode runtime correctness. Token-claim mitigation: recommend native tool_output caps and compaction configuration as a strictly-less-invasive path to recover token budget without injecting rewrite hooks. [snip docs; OpenCode config docs] (knowledge/res011-opencode-snip-mechanical-lock/sources/github-com-edouard-claude-snip.md; knowledge/res011-opencode-snip-mechanical-lock/sources/opencode-ai-v2-docs-compaction.md)

9. Recommendation (bottom line)
- Remove opencode-snip from recommended plugin set (safe removal — 0 recorded dependents) and instead: (a) tighten native OpenCode output caps (tool_output.max_lines, max_bytes), (b) enable compaction/prune reserved strategies, and (c) publish operational guidance for projects that require token savings to migrate to explicit snip binary usage (snip proxy) under developer control. This approach minimizes permission-matching regressions while preserving token-economy benefits for opt-in users. [synthesized from multiple archived sources above]
